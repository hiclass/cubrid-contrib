02실화면 — 드릴다운

지도에서 셀을 고르면 섹터 → 페이지 → 슬롯이 이어서 열린다. 오른쪽 4박스가 각각 한 계층이다.

cbench 12GB 볼륨 · 150×44 · 실제 pty 캡처를 ANSI→HTML로 렌더
  • 지도 — 1칸 = N페이지. 색은 소유 파일 종류, 채움 램프 는 할당률
  • sector — 섹터 하나 = 64페이지. 한 칸이 페이지 1개
  • page — 16KB 한 장의 바이트 지도. hdr/rec/free/dir/frag 구분
  • slots — 레코드 자리. H N R B D d A - ? 9종을 구분 표시
  • info — 지금 고른 것의 정체. 하단 2줄은 항상 전체 상세를 유지
손상을 감추지 않는다. 미할당은 (unallocated), 할당된 이상값은 corrupt?로 그대로 노출한다. 슬롯이 없는 페이지는 왜 없는지까지 알린다 — slots n/a - qresult page.

04설계 — 왜 안전한가

원칙구현
서버 무접촉볼륨 파일을 O_RDONLY로 직접 해석. 페이지 버퍼·락 테이블 미접근
락 0 / 쓰기 0파일 락 미사용. fd는 읽기 전용
읽기 최소기본은 볼륨당 헤더 + 섹터테이블 + 파일테이블만
오프셋 하드코딩 0온디스크 구조체를 엔진 헤더에서 #include — 오프셋은 컴파일러가 계산
자기검증 3중볼륨 magic / FILE_HEADER self VFID / 페이지 prv.pageid

기동 중 DB와 정지된 DB에서 동일하게 동작한다(CS/SA 구분 없음).

05아키텍처

2-패스 수집 — Pass 1은 볼륨 바이너리 직접 해석(항상), Pass 2는 서버가 있을 때만 카탈로그로 신선도를 확인한다. 서버가 없으면 자동 생략되고 기능 저하는 없다.

3 레인 스레드 — 콜드 캐시에서 동기 I/O가 UI를 멈추던 문제를 레인 분리로 해결했다.

레인역할효과(실측)
UI입력·렌더만. I/O 없음콜드 refresh 6.95s 무응답 → ≤0.1s
워커 A스캔·refresh·deep. 섀도 버퍼 재구축 후 포인터 스왑콜드 스캔 1.61s → 33ms
워커 B드릴다운 섹터 읽기. 큐 깊이 1콜드 오버레이 575ms → 29ms
temp 볼륨은 수명이 짧다. <db>_t<N>은 vinf에 없고 쿼리가 spill하는 동안만 존재한다. [r]마다 디렉터리를 재스캔해 새로 생긴 것은 넣고 사라진 것은 뺀다 — 워커가 볼륨 배열을 훑는 중이면 끝날 때까지 기다린 뒤 바꾼다.

06배포 & 사용

바이너리특성
cub_volmap완전 정적, 의존 0. 어느 서버에나 파일 하나로 복사
cub_volmap-dynglibc 동적. 런타임 dlopen으로 라이브 오버레이 가능
# 배치 — 지도 + 정합성 소견
cub_volmap --check --plain <db>

# 인터랙티브 — 마우스·화살표로 드릴다운
cub_volmap -i <db>

# 캐시 상주율 + 서버 버퍼풀 중첩
cub_volmap -i -m --bufmap=/tmp/bcb.dump <db>

# 기계 가독
cub_volmap --check --format=json <db> -o out.json
같은 이름의 DB가 여러 설치본에 있으면 databases.txt 해석이 의도와 달라질 수 있다. vinf 경로를 직접 주면 모호함이 없다 — cub_volmap -i /path/to/<db>_vinf
